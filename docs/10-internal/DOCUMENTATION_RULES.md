## ⚠️ КРИТИЧЕСКИ ВАЖНЫЕ ПРАВИЛА

Эти правила **обязательны** к исполнению при любой работе с кодом проекта.

---

## 1. Правило версионирования

### При ЛЮБОМ изменении кода:

1. **Создать файл версии** `docs/09-versions/v{MAJOR}.{MINOR}.md`
   - Если версия новая (изменилась MAJOR или MINOR)
   - Использовать шаблон из `docs/09-versions/README.md`

2. **Обновить `docs/CHANGELOG.md`**
   - Добавить запись в таблицу версий
   - Формат: `| **{version}** | {date} | {status} | {description} | [файл](versions/файл.md) |`

3. **Обновить `docs/overview.md`**
   - Изменить версию в заголовке
   - Добавить запись в историю версий (таблица в начале файла)

4. **Включить в коммит**
   - Файл версии
   - CHANGELOG.md
   - overview.md (если изменилась версия)

## 3. Типы изменений и версионирование

| Тип изменения | Пример | Версия |
|---------------|--------|--------|
| **MAJOR** (breaking changes) | Удаление API, изменение контракта | 6.0 → 7.0 |
| **MINOR** (новые фичи) | Новый сервис, хендлер | 6.1 → 6.2 |
| **PATCH** (багфиксы) | Исправление ошибки | 6.1.1 → 6.1.2 |

**В проекте используется:** `{MAJOR}.{MINOR}` (PATCH не используется)

## 4. Чек-лист перед коммитом

```
[ ] Изменился код? → Создан файл версии?
[ ] CHANGELOG.md обновлён?
[ ] overview.md обновлён?
[ ] Все 3 файла закоммичены?
[ ] commit message включает версию?
```

## 7. Настройки в .qwen/settings.json

```json
{
  "documentation": {
    "docs_root": "docs/",
    "versioning_required": true
  },
  "versioning_rules": {
    "on_code_change": {
      "create_version_file": true,
      "update_changelog": true,
      "update_overview_version": true,
      "commit_message_include_version": true
    }
  }
}
```

## 8. Нарушение правил

**НЕЛЬЗЯ:**
- ❌ Коммитить код без файла версии
- ❌ Обновлять код без обновления CHANGELOG
- ❌ Использовать устаревшие файлы из PROMPTS/

**МОЖНО:**
- ✅ Пропустить создание версии для документации (не кода)
- ✅ Объединять PATCH изменения в один файл версии
