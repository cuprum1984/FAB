# 🔒 Лимиты Free плана

**Версия:** 6.4 (31 марта 2026)
**Статус:** ✅ Реализовано

---

## 📋 Обзор

Сервис ограничения ресурсов для защиты от злоупотреблений в бесплатной версии бота.

**Назначение:**
- Защита от создания тысяч источников одним админом
- Ограничение нагрузки на сервер
- Предотвращение коммерческого использования Free версии

---

## 🎯 Лимиты

| Ресурс | Лимит | Обоснование |
|--------|-------|-------------|
| Telegram-каналов | 15 на админа | Личное использование + несколько проектов |
| YouTube-каналов | 10 на админа | YouTube парсинг более ресурсоёмкий |
| **Всего источников** | **25 на админа** | Суммарный лимит (TG + YouTube) |
| Управляемых групп | 5 на админа | 1 личная + 3-4 проекта |
| Топиков в группе | 20 на группу | Достаточно для категоризации |

## 🔧 API

### `check_source_limit(user_id, session, source_type)`

Проверить лимиты пользователя на источники.

**Параметры:**
- `user_id` (int) — ID пользователя
- `session` (AsyncSession) — сессия БД
- `source_type` (str, optional) — тип источника: "telegram", "youtube", None (все)

**Возвращает:**
```python
{
    "ok": True/False,
    "current": {"telegram": 5, "youtube": 3, "total": 8},
    "limits": {"telegram": 15, "youtube": 10, "total": 25},
    "error": "text"  # если ok=False
}
```

**Пример использования:**
```python
from core.services.limits import check_source_limit

result = await check_source_limit(
    user_id=callback.from_user.id,
    session=session,
    source_type="telegram"
)

if not result["ok"]:
    await callback.message.answer(result["error"])
    return
```

## ⚠️ Важные решения

### 1. Проверка ДО добавления в БД

**Решение:** Проверять лимит перед коммитом в базу данных.

**Почему:**
- Пользователь сразу видит ошибку
- Не создаются «мусорные» записи в БД
- Проще откатить операцию

---

### 2. Сообщение об ошибке с контекстом

**Решение:** Показывать текущие значения и лимиты.

**Пример:**
```
🚫 Превышен лимит Telegram-каналов: 15 из 15

📊 Текущие значения:
• Telegram: 15
• YouTube: 2
• Всего: 17

📋 Лимиты Free плана:
• Telegram: 15
• YouTube: 10
• Всего: 25
```

**Почему:**
- Пользователь понимает, какой лимит превышен
- Видит общую картину использования ресурсов
- Может принять решение (удалить старый источник или добавить новый)

---

### 3. Сохранение message_id после ошибки

**Решение:** Сохранять `message_id` меню после показа ошибки.

**Почему:**
- При нажатии на кнопки меню обновляется то же сообщение
- Не создаются новые сообщения (спам)
- Сохраняется единая точка навигации

**Реализация:**
```python
# Сохраняем message_id перед очисткой
data_before_clear = await state.get_data()
menu_message_id = data_before_clear.get(MENU_MESSAGE_ID_KEY)

# Очищаем состояние
await state.clear()

# Восстанавливаем message_id
if menu_message_id:
    await state.update_data({MENU_MESSAGE_ID_KEY: menu_message_id})
```
