# Версия 6.9.9 — SSL certifi, фикс сертификатов t.me

**Дата:** 24 мая 2026  
**Статус:** Актуальная  
**Автор:** Sisyphus

## 📋 Обзор

Исправление ошибки `SSL: CERTIFICATE_VERIFY_FAILED` при подключении к `t.me` на системах без актуального Certificate Trust List (чистая Windows, minimal Docker). Парсер Telegram использует теперь `certifi` для создания SSL-контекста — это гарантирует кросс-платформенную работу независимо от системного хранилища сертификатов.

## 🔧 Изменения

- **`core/parser/telegram.py`**: добавлены `import ssl` + `import certifi`, создан модульный `_SSL_CTX` через `ssl.create_default_context(cafile=certifi.where())`, передаётся как `ssl=_SSL_CTX` в оба `session.get()` (функции `check_channel_exists` и `get_channel_title`)
- **`core/parser/telegram_posts.py`**: те же импорты и `_SSL_CTX`, передаётся в `session.get()` внутри `get_new_posts`

## 🐛 Исправления

- `SSL: CERTIFICATE_VERIFY_FAILED: self-signed certificate in certificate chain` при GET-запросах к `t.me/s/{username}` на системах без корневого сертификата ISRG Root X1 / Cloudflare CA в системном хранилище

## ⚠️ Известные проблемы

- `certifi` уже присутствует как транзитивная зависимость (`requests`), новых требований в `requirements.txt` не добавлялось
- На Linux `certifi` не конфликтует с системным `ca-certificates` — работает поверх
