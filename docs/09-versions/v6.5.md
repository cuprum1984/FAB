---

### Управление сообщениями

**Используется:** `bot/utils/menu_message.py`

**Логика:**
1. `message_id` сохраняется в FSM состоянии (`_menu_message_id`)
2. При навигации — `edit_message_text` (то же сообщение)
3. При оплате — удаление старого + новое сообщение
4. Новое главное меню — новый `message_id`

**Важно:** При выходе из меню поддержки `message_id` сохраняется для последующей навигации!

## ⚠️ Известные проблемы

### 1. Invoice — отдельное сообщение

**Проблема:** Telegram API отправляет Invoice как отдельное сообщение (не edit).

**Решение:** После оплаты удаляем меню донатов, отправляем спасибо + новое меню.

---

### 2. Перехват callback'ов

**Проблема:** `debug_callbacks` из `settings_handler.py` перехватывал `support_settings` и `support_back`.

**Решение:**
1. Подключить `support.router` **раньше** `settings_handler.router`
2. Добавить `settings_support` в исключения `debug_callbacks`

---

### 3. Сброс message_id при очистке состояния

**Проблема:** `state.clear()` удалял `message_id`, создавались новые сообщения.

**Решение:** Сохранять `message_id` перед `state.clear()` и восстанавливать после:

```python
# Сохраняем
data = await state.get_data()
menu_message_id = data.get(MENU_MESSAGE_ID_KEY)

# ... операции ...

# Восстанавливаем
await state.clear()
if menu_message_id:
    await state.update_data({MENU_MESSAGE_ID_KEY: menu_message_id})
```
