## 🔄 Flow верификации и блокировки

```
Автор пишет разработчику (@)
  ↓
Разработчик: python scripts/generate_verification_code.py username
  → VRF-A3KX9P
  ↓
Автор размещает код одним из способов:
  1. В описании канала (bio) — временно, на 5 минут ✅
  2. Или публикует постом в канале ✅
  ↓
Разработчик видит код → запускает:
  python scripts/block_source.py username
  → Скрипт показывает ожидаемый код → сверяет
  ↓
Подтверждение (y/N)
  ↓
is_blocked = TRUE
Удаляем подписки и назначения (CASCADE)
  ↓
Автор убирает код из bio/поста
```

### Два способа верификации:

| Способ | Плюсы | Минусы |
|--------|-------|--------|
| **Описание канала (bio)** | Быстро, не спамит подписчикам | Нужно зайти в настройки |
| **Пост в канале** | Привычнее, виден всем | Спамит подписчикам |

## ⚠️ Важные решения

### Почему не удаляем ContentSource?
Запись сохраняется для учёта: если пользователь попытается добавить заблокированный канал снова, бот найдёт запись и откажет.

### Почему только ручной скрипт?
- ❌ Нет команды `/block` в боте (только разработчик)
- ❌ Нет админ-панели для блокировки
- ❌ Не автоматизируем по жалобам (риск злоупотреблений)

### Каскадное удаление
При блокировке удаляются:
1. `TopicSourceAssignment` (через subscription_id)
2. `SourceSubscription` (по source_global_id)

Сам `ContentSource` остаётся с `is_blocked=True`.
