📋 ПОЛНЫЙ ТЕХНИЧЕСКИЙ ПРОМПТ ПРОЕКТА MyAggryBot (ФИНАЛ)

Версия: 6.0 (Обновлено 19 февраля 2026)
Статус: ГОТОВО К ЗАПУСКУ 🚀
🎯 БАЗОВАЯ КОНЦЕПЦИЯ

Telegram-бот для автоматического мониторинга и доставки контента из Telegram и YouTube каналов в группы с поддержкой тем (forum topics). Бот работает исключительно на чистом Bot API, без использования MTProto.

Ключевые требования:

    Автоматический мониторинг источников.

    Отправка новых постов в указанные темы групп.

    Удобный интерфейс для управления подписками.

    Безопасность и защита от SSRF.

    Масштабируемая архитектура (PostgreSQL, Redis).

🔥 ИСТОРИЯ КЛЮЧЕВЫХ ТЕХНИЧЕСКИХ ПРОБЛЕМ И ИХ РЕШЕНИЯ
1️⃣ Telegram: Множественные посты после отключения бота

    ❓ Проблема: При запуске после простоя бот находил все новые посты, но отправлял только первый. База данных обновлялась после каждого поста, и последующие в том же цикле считались старыми.

    ✅ Решение: Сохранять исходный last_successful_post_id перед циклом. Обновлять запись в БД только один раз в конце — самым последним успешно обработанным ID.
    python

    # core/services/monitoring_service.py
    current_last_id = source.last_successful_post_id
    last_successful_id = None
    for post in new_posts:
        await self._process_telegram_post(post, source, assignments, session, current_last_id)
        last_successful_id = post['post_id']

    if last_successful_id:
        await update_source_last_post_id(source, session, int(last_successful_id))

    📁 Затронутые файлы: monitoring_service.py

2️⃣ YouTube: Эволюция парсера (От RSS к простоте)

    ❓ Проблема 1 (Brand Accounts): Парсер мог найти неверный channel_id, принадлежащий другому автору (например, из Brand Account), так как в HTML их может быть несколько.

        ⚰️ Устаревшее решение (RSS-эпоха): Сравнение названия канала из HTML с названием из RSS-ленты.

    ❓ Проблема 2 (Крах RSS): В сентябре 2025 YouTube отключил публичные RSS-ленты. Запросы к /feeds/videos.xml?channel_id=... стали возвращать 404.

    ❓ Проблема 3 (Динамический контент): Контент на странице /videos подгружается динамически через JavaScript и отсутствует в сыром HTML, получаемом через aiohttp.

    ✅ Финальное решение (Предельно простой HTML-парсер):

        Принцип: Человек видит на вкладке /videos первое видео — оно и есть самое новое. Нам не нужно больше ничего.

        Реализация: Парсер ищет первое вхождение паттерна с ID видео (11 символов) в HTML-коде страницы youtube.com/@username/videos. Это надежно, быстро и не зависит от JavaScript.

        core/parser/youtube_simple.py:
        python

        # Поиск channel_id
        re.search(r'<meta property="og:channel:id" content="(UC[^"]+)"', html)
        # Поиск первого видео
        re.search(r'data-id="([a-zA-Z0-9_-]{11})"', html)
        # Валидация
        if len(video_id) == 11: ...

    📁 Затронутые файлы: youtube_simple.py (новый), sources.py (обновлен), youtube_simple_service.py (новый).

3️⃣ YouTube: "Ленивая" загрузка контента

    ❓ Проблема: При первом запросе к каналу YouTube может не отдать данные о последнем видео (кеш не сгенерирован). Повторный запрос через несколько секунд часто возвращает корректные данные.

    ✅ Решение (User Experience): Добавлена автоматическая повторная попытка с понятным сообщением для пользователя.
    python

    # bot/handlers/sources.py
    channel_data = await youtube_parser.get_channel_data(username)
    if not channel_data:
        await message.answer("⏳ YouTube канал ещё грузится, пробую ещё раз через 3 сек...")
        await asyncio.sleep(3)
        channel_data = await youtube_parser.get_channel_data(username)

4️⃣ Telegram: Встроенный плеер YouTube

    ❓ Проблема: Если отправить ссылку на YouTube внутри подписи к медиа, Telegram не активирует встроенный плеер.

    ✅ Решение: Отправлять ссылку отдельным текстовым сообщением с опцией disable_web_page_preview=False.
    python

    await bot.send_message(
        chat_id=..., text=f"https://youtu.be/{video_id}\n\n...",
        disable_web_page_preview=False
    )

    📁 Затронутые файлы: sources.py

5️⃣ Инфраструктурные проблемы

    ❓ Кириллические URL: Telegram преобразует кириллицу в percent-encoding (%D0%9E%D0%B1...).

        ✅ Решение: Декодировать URL перед обработкой (urllib.parse.unquote).

    ❓ Brotli сжатие: YouTube отдает страницы в сжатии Brotli.

        ✅ Решение: Установка библиотек brotli и brotli-asgi.

    ❓ DNS и aiodns: Библиотека aiodns вызывала конфликты.

        ✅ Решение: Отказ от aiohttp[speedups] и aiodns в пользу чистой установки aiohttp.

Если вам понадобится объяснить этот проект другой LLM (например, для генерации кода или поиска багов), используйте этот сжатый промпт:

    Проект MyAggryBot — Telegram парсер контента.

    Технологии: aiogram 3.x, SQLAlchemy 2.0+, asyncpg, PostgreSQL, Redis, aiohttp, BeautifulSoup4.

    Ключевая бизнес-логика:

        Telegram: Парсинг публичных каналов через t.me/s/. В мониторинге критично обрабатывать пачку новых постов и обновлять last_post_id в БД только один раз после обработки всей пачки, чтобы избежать пропуска постов.

        YouTube: Используется упрощенный HTML-парсер. RSS отключен. Парсер заходит на страницу youtube.com/@username/videos и ищет первое видео по паттерну data-id="[a-zA-Z0-9_-]{11}". ID видео всегда 11 символов. Добавлена повторная попытка через 3 секунды при ошибке, так как YouTube иногда "лениво" генерирует контент.

        Отправка в Telegram: Ссылки на YouTube отправляются отдельным текстовым сообщением с disable_web_page_preview=False для активации встроенного плеера.

        Безопасность: Все входные данные проходят через urllib.parse.unquote. URL проверяются по белому списку доменов (youtube.com, youtu.be, t.me, telegram.org) для защиты от SSRF.

        Базы данных: PostgreSQL — основное хранилище (пользователи, группы, темы, источники, подписки). Redis — кеш последних ID для быстрой проверки дублей.

        Архитектура: Мультитенантная. У каждого пользователя свои группы и подписки. Админ-панель общая, но контекстная.
