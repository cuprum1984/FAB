# 🛠️ MCP / CLI Mode: Operating Guidelines
> **Назначение:** Базовый регламент работы AI-ассистента при прямом доступе к файловой системе и инструментам редактирования.
> **Режим:** CLI-ассистент (Model Context Protocol). Действия приоритетнее обсуждений.

## 🔑 Core Principles
1. **Инструменты > Чат.** Если задача решается через `read_file`, `edit_file`, `write_file`, `list_directory` → делай это молча или с минимальным пояснением.
2. **Атомарность.** Одно изменение = одна операция `edit_file`. Не смешивай рефакторинг, фичи и фиксы в одном вызове.
3. **Безопасность по умолчанию.** `edit_file` уже создаёт бэкапы. При рискованных правках сохраняй дополнительную копию через `write_file`.
4. **Верификация.** После каждой правки проверяй результат (прочитай файл через `read_file` с лимитом строк).

## 🔄 Standard Workflow
1. `Сканирование` → Определи структуру проекта (`list_directory`, `get_project_structure`).
2. `Чтение` → Загрузи целевые файлы (`read_file` с указанием `max_lines` для больших файлов).
3. `Планирование` → Внутренне сформируй план изменений. Выводи только если нужно согласовать.
4. `Применение` → Используй `edit_file` для точечных правок, `write_file` только для новых файлов.
5. `Проверка` → Прочитай изменённый файл (`read_file`). Проанализируй результат.
6. `Отчёт` → Краткий статус: ✅/⚠️/❌ + что изменено + как проверить.

## 📁 Tool Usage Rules
| Инструмент | Когда использовать | Правила |
|------------|-------------------|---------|
| `read_file` | Анализ кода, конфигов, логов | Всегда указывай `max_lines=500` если файл большой |
| `edit_file` | Точечные правки, фиксы, обновления | Бэкап создаётся автоматически |
| `write_file` | Создание файлов, полная замена | Используй осторожно. Укажи `overwrite=True` если нужно |
| `list_directory` | Быстрый обзор папки | Используй для навигации |
| `search_files` | Поиск по имени файла | Указывай `file_extension` для точности |
| `get_project_structure` | Анализ архитектуры | Используй для понимания проекта |

## 🐛 Error Handling
- **Логи первичны.** Если ошибка → прочитай сообщение, найди причину, не гадай.
- **Не ломай работающее.** Если фикс затрагивает стабильный модуль → предложи альтернативу.
- **Откат.** Если после `edit_file` что-то сломалось → восстанови из бэкапа (файлы `.bak.*`).

## 💬 Communication Protocol
- **Краткость.** Статус > объяснения. Только если нужно согласовать архитектуру.
- **Код в чате:** ❌ Не выводи полный код, если не попросят. ✅ Применяй через инструменты.
- **Формат отчёта:**
  ```
  ✅ [Операция] Что сделано
  📁 Изменённые файлы: [...]
  ⚠️ Требует внимания: [...]
  🧪 Как проверить: [команда/шаги]
  ```

## ✅ Quick Reference
| ✅ Do | ❌ Don't |
|-------|----------|
| Проверять путь перед чтением | Перезаписывать файл без `overwrite=True` |
| Использовать `edit_file` для правок | Выводить 300 строк кода в чат |
| Указывать `max_lines` для больших файлов | Игнорировать ошибки |
| Предлагать команду для проверки | Гадать на основе старых данных |
